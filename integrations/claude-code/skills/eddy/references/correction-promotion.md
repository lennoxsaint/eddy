# Correction-to-eval promotion

Eddy records durable owner learning through:

`owner verdict -> generalized correction -> regression eval -> current-run repair -> owner-profile candidate -> generic-doctrine candidate -> projection verification`

`owner-verdict-v2` requires each issue to name:

- the artifact and timestamped or visible evidence;
- the immediate desired correction;
- a narrow generalized rule;
- a correction-specific `eval_id`;
- a source reference;
- `promotion_class`: `project_specific`, `owner_profile`, or `generic_candidate`;
- `project_fact_fields`, which must be empty for any reusable candidate.

Current-run repair happens immediately. Owner-profile promotion requires the new eval to pass.
Generic promotion additionally requires cross-project recurrence or explicit Lennox designation.
Names, spellings, URLs, prices, currency, CTAs, logos, runtime targets, speaker palettes, and
one-off visual choices remain project facts. Literal URLs and offer amounts also fail the
anti-overfitting validator. Private raw session text is never copied into the skill.

Historical profiles, verdicts, plans, and receipts remain immutable. Promotion creates a new
version; rollback selects the prior version and restores projections from recorded hashes.
